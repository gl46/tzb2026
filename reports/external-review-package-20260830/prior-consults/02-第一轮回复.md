# 总判断

四个问题里,最需要先纠正的不是某个参数,而是两条因果叙事:

1. **95.3 mm 的稳定接触偏差,更像坐标链/TCP/受控末端定义错误,不像"抓取任务本来就很难"。**官方 Franka hand 描述里,`hand → hand_tcp` 的默认轴向平移正好是 **103.4 mm**;它与 95.3 mm 只差 8.1 mm。这不是定论,因为实际 Isaac USD 和 IK 求解器可能控制的是别的 frame,但它已经足以成为下一版本的第一排查项。
2. **经典执行层失败,不能被表述为"所以需要大模型来救"。**TCP 错位是低层几何问题,大模型不会自动修好它。正确叙事是:严格协议暴露了低层执行瓶颈,而分层架构使这个瓶颈可隔离、可替换、可验证,没有污染高层语言理解与任务规划的声明。

本轮冻结的 12 次继续原样完成。下面所有"修复、阈值、协议改造"都应进入**新的版本身份、新的预注册**,不回填、不覆盖旧结果。

# 问题 1|经典规划基线成功率过低

## 1.1 95.3 mm 系统性偏差:建议按这个顺序排查

### 第一优先级:IK 控制的 frame 和你定义的抓取 TCP 不是同一个

先把以下四个 frame 明确区分,禁止再统称"末端":

- `link8`:机械臂最后一节连杆;
- `hand`:夹爪基座;
- `hand_tcp`:官方定义的工具中心点;
- `finger_mid/contact_frame`:真正希望两指夹住物体的位置。

最危险的情况是:IK 求的是 `hand` 或 `link8`;抓取合成器输出的是 `hand_tcp` 或指尖中点;接触门比较的又是另一个 frame。即使每段代码都"没有 bug",这三者语义不同也会稳定地产生约 10 cm 偏差。

### "末端自洽试验"(约 30 分钟,独立调试身份下)

1. 暂停物理;选 5 个分散的合法关节姿态。
2. 对每个姿态同时记录:Isaac USD 中 `link8`、`hand`、`hand_tcp`、左右指尖的世界位姿;规划器 FK 对它所声称的 end-effector frame 算出的位姿;左右指尖接触面的几何中点。
3. 验证固定变换 W_T_TCP == W_T_E · E_T_TCP 是否成立。
4. viewport 中给这些 frame 各画 XYZ 三轴,肉眼看目标轴是否落在夹爪中心。
5. 调试自洽门(非任务门):静态位置差 <1 mm、静态角度差 <0.5°。

再做两个判别力很强的测试:

- **当前位姿回灌测试**:读当前受控 frame 位姿原样作 IK 目标,解应接近当前关节角、误差接近数值精度;
- **单位轴脉冲测试**:目标世界坐标各加 +10 mm X/Y/Z,看实际受控 frame 是否沿对应世界轴移动 10 mm。

回灌都不自洽,就不要继续查抓取采样或控制器。

## 1.2 第二优先级:变换方向、乘法次序、四元数顺序

记法:A_T_B 把 B 系的点变换到 A 系。O=物体,G=抓取/TCP,E=IK 实际控制的末端,W=世界。

- 目标链:W_T_G = W_T_O · O_T_G。
- IK 控制 E 而抓取定义 G 时:W_T_E* = W_T_G · (E_T_G)^(-1)。
- 易错:忘最后一个逆;T_EO 当 T_OE;行/列向量混用;pre-grasp 偏移左乘到世界坐标而非右乘工具局部坐标(局部进近 −Z 应为 W_T_pre = W_T_G · Trans_G(0,0,−d),右乘才随夹爪方向旋转)。
- Isaac 四元数约定不统一:Core API 是 scalar-first (w,x,y,z);Read World Pose OmniGraph 节点输出近似 (x,y,z,w)。跨接口无显式转换会产生方向相关大偏差。

### 用"误差在哪个坐标系恒定"定位

| 残差特征 | 最可能根因 |
| --- | --- |
| TCP 系中恒约 [0,0,0.10] m | 漏了 hand→TCP 或 finger-center 偏移 |
| 世界/基座系中方向恒定 | world/base 注册、局部/世界 pose 混用 |
| 随夹爪姿态旋转 | 逆变换、乘法次序、四元数顺序 |
| 接近一个格位节距(90–100 mm) | 行列索引、中心/角点、0/1 起始编号 |
| 随速度增长、减速消失 | 控制器跟踪滞后 |
| 物体稳定后数值变化大 | 物体位姿读取过早或时间戳错位 |

同时检查 95.3 mm 是否接近一个料箱格子的中心距("第二排第三格"算成相邻格)。

## 1.3 第三优先级:把 IK、动态跟踪、场景漂移拆开

每个物理步分别记录四种残差(不必线性相加):r_IK = FK(q_cmd)−p_target;r_track = FK(q_actual)−FK(q_cmd);r_scene = p_object,now−p_object,plan;r_gate = p_measured−p_desired。带 physics frame id、仿真时间、物体 pose 读取时刻、轨迹下发时刻、门判定时刻、q_cmd/q_actual、目标 frame 名称与 prim path。

### 决定性分流实验

同一目标:求 IK → 暂停物理 → teleport 到求得关节角 → 测 TCP 误差。

- teleport 后仍 95 mm:坐标链/模型/frame 定义/门参考点错误;
- teleport 后≈0 但动态执行后 95 mm:控制器、驱动目标、碰撞或检查时机;
- 空场正常、接触场异常:碰撞/刚度/控制增益/接触不可达。

(Isaac 文档:仿真停止时关节直接跳到目标;运行时写的是 joint drive target,受接触碰撞影响不保证精确到达。)

### 物体位姿读取改状态门

线速度 <5 mm/s、角速度低于小阈值、连续满足 5–10 physics steps 后再读 pose;到达 pre-grasp 后最终接近前再刷新一次。不要"固定等 20 帧"。

### 接触门应测"接触",不能测"某两个原点距离"

若门比较的是 hand 原点到物体中心/TCP 到物体中心/视觉 mesh 原点到夹爪原点,95 mm 甚至可能是"正确到达但量错位置"。下一版直接用 PhysX contact point、接触刚体对、是否落在 finger pad 指定区域、接触法向与数量、两侧接触对称性(Isaac Contact Sensor 基于 PhysX Contact Report)。

## 1.4 一周内最值得实现的成功率改进(全部用于新版本/演示支路)

**A. 确定性候选集 + 硬过滤 + 排序**(16–32 候选:顶抓/侧抓 × 4–8 yaw × 主轴少量偏移,对称去重)。硬门顺序:抓取宽度→pre-grasp IK→grasp IK→进近扫掠不撞箱壁→关节不贴极限→闭合后有夹持空间。排序用字典序(最小碰撞间隙最大→关节裕量最大→可操作度→路径短),不要一开始就加权成神秘分数;保留前三候选做固定顺序 fallback,失败换下一候选不重新随机采样。

**B. 最后 40–60 mm 不用一次性开环笛卡尔插值**:大范围关节空间碰撞感知规划→箱口上方固定路标→最后 40–60 mm 差分 IK/短周期 Cartesian servo,每步重读实际 TCP 按实际误差更新。到位判收敛门(TCP 位置 <2–3 mm、关节 <0.01 rad、TCP 线速度 <5 mm/s、连续 5–10 步),不用固定 sleep。(Isaac 官方 pick-and-place 有 PINK differential IK;Path Planner 出 configuration-space waypoints。)

**C. pre-grasp 局部搜索**:平移 x,y∈{0,±5,±10 mm}、yaw∈{0,±5°},每候选重跑短程 IK+碰撞。调试支路可用 GT pose 做上界试验区分感知/执行误差,正式声明必须注明 GT oracle 不属于完整系统。

**D. 放置拆五段**:垂直抬升到箱沿上方 30–50 mm→安全高度水平移动到目标格位上方→垂直下降→支撑面上方 3–5 mm 释放→垂直撤离。稳定后判定:完全位于格位内、无非法壁重叠、静止、姿态满足。

**E. 目标点选"最大内切圆中心"而非格位几何中心**:可行区域 F = C ⊖ P_θ ⊖ M(格位区域收缩掉旋转零件足迹与误差裕量),取 F 中离边界最远点——"容差漏斗"的严格几何版。

## 1.5 20 mm 门限是否合理

不能脱离几何谈合理性:宽松料箱投放可容忍厘米级;精密插装可到 0.1 mm 且依赖力控。应推导而非引用"工业通用标准":

- m_x = (W_cell − W_obj,eff(θ))/2 − c_wall − b_x;m_y 同理;
- W_obj,eff = |w·cosθ|+|l·sinθ|,H_obj,eff = |w·sinθ|+|l·cosθ|;
- c_wall=壁面间隙,b=感知+控制+抓后漂移+释放滚动误差预算;无独立性证据先最坏情况相加。
- 例:格位 60 mm/零件 30 mm→每轴纯几何余量 15 mm,20 mm 径向门可能已允许撞壁;格位 100 mm/零件 30 mm→余量 35 mm,20 mm 偏保守。

下一版拆三判据:①抓取接触成功(finger pad 与目标产生指定接触,非 TCP 距物心 <20 mm);②轨迹到位精度(目标 vs 实际 TCP 位姿误差);③放置任务成功(几何包含+稳定+无非法碰撞)。

## 1.6 下一版评测协议:先判实现有效,再判任务难度

当前规则的统计事实(材料措辞必须说准):

- n=12、p0=0.75、X≤5 拒绝:实际一类错误率 P_{0.75}(X≤5)=0.01425(比 0.05 保守);
- 真实 p=0.5 时拒绝概率仅 P_{0.5}(X≤5)=0.3872(不擅长区分 50% 与 75%);
- "≥6/12 未拒绝"**不能**写成"证明成功率≥75%";单侧 95% 精确置信下界要超 0.75,n=12 需 12/12(下界≈0.779)。

**三层新协议**:

1. **实现有效性 fixture**(不做概率声明):当前位姿回灌;空场 XYZ 各 10 mm;3 个已知可达宽容差正对照;3 个必须被拒的负对照;GT pose+teleport;GT pose+动态控制。正对照失败=实现无效停端到端;负对照被接受=门无效。
2. **分阶段表征集**:只记录第一个失败阶段(pose 稳定→有合法候选→pre-grasp IK→grasp IK→末端收敛→真实接触→夹持→运输→放置包含→放置稳定),报告 P(IK|candidate)、P(contact|IK)、P(place|transport) 与无条件端到端成功率。
3. **独立端到端确认集**:单一主声明避免多重检验。参考设计:H0: p≥0.75 vs p1=0.50,n=26、X≤15 拒绝,一类错误≈4.01%,对 p=0.50 功效≈83.65%。样本数由 (p0,p1) 与成本预先计算;小样本区间报精确或 Wilson。

# 问题 2|少于 1000 行是否微调 27B 多模态

## 2.1 战略:ICL 做主路径,LoRA 做受控实验

<1000 行不等于 LoRA 无效(可学标签映射、输出格式、利用既有视觉特征),但难以重新教会视觉塔新的细粒度概念。本周决策顺序:①冻结强 zero-shot 系统提示→②dev 上调优 2–4 shot ICL→③冻结提示与例子→④保守 QLoRA→⑤只有 QLoRA 在独立测试稳定超过调优 ICL 才作亮点→⑥否则部署 ICL 并如实报告。不让 LoRA 成为材料单点依赖。

## 2.2 稳妥起点配置(假设 A100 80GB;40GB 则 4-bit 必需)

| 项目 | 建议起点 |
| --- | --- |
| 基座 | 语言主干 4-bit NF4,double quant,BF16 compute |
| 视觉塔 / projector | 冻结,BF16 |
| LoRA 目标 | named_modules() 审计确认的语言主干投影;排除视觉塔、projector、embedding、lm_head、MTP;不要用 all-linear |
| rank / alpha / dropout | r=8 / 16 / 0.05(步数极少时另留 0.0 作 dev 候选) |
| 学习率 | 先 1e-6(协调注:此值偏保守,owner 自行评估) |
| epoch | 2,最多 3 |
| 有效 batch / warmup / sched / wd / clip | 16 / 3–5% / cosine / 0.01 / 1.0 |
| 评估 | 每 epoch ≥4 次;只由 dev 主指标选 epoch,测试只读一次 |

开 gradient checkpointing;训练/测试同一图像分辨率策略;半个 epoch 没提升先查 masking/目标 token/LoRA 挂载/梯度非零,不要加 epoch 到 10–20。

**selected-logit CE 三检查**:①每选项对应单一唯一 token(固定 A/B/C;勿假设中文词是单 token);②训练评估同一组选项 token id 同顺序;③真实生成 sanity check(能输出合法选项与 JSON)。

## 2.3 最应防的失败模式

- **A. 只学会答案先验/问题模板**:必做 question-only、blank-image、shuffled-image 三反事实基线;打乱图片准确率几乎不降=没学视觉。
- **B. 固定背景捷径**:按 episode/source component 分组;分任务类型分层准确率;选项顺序置换检查;轻微合法光照变化稳定性检查。
- **C. 统计单位必须是源 episode/近重连通分量**,不是 QA 行(同图两行错误高度相关)。
- **D. 量化收益误当微调收益**:四对照——BF16 base;同 QLoRA 的 4-bit base;4-bit+调优 ICL;4-bit+QLoRA。
- **E. 只看训练 loss**:<1000 行训练 loss 归零不提供外推证据;主判断来自 dev/合成测试/人工盲测。

## 2.4 ICL 与 LoRA 公平对照

预冻结:system prompt、示例数、选择策略、分辨率、decoding、选项顺序、解析器。ICL 示例只来自 train 且不与测试图同近重/来源分量。实用差异门(防偶然翻转包装成收益):QLoRA 相对调优 ICL ≥+5 pp,或每 20 独立 episode 至少少错 1 个,且人工盲测不退化;差值置信区间不显示明显负收益。

## 2.5 诚实的成对评测

成对表(n11/n10/n01/n00),重点披露 n01(纠正)、n10(破坏)、净改进。二元结果小样本用 **exact McNemar**(不依赖大样本卡方)。准确率/macro-F1/Brier/selected-logit NLL 差用 **10,000 次 paired cluster bootstrap**,以源 episode/近重分量为单位整组重采样。报告格式示例:"+4.2 pp,cluster-bootstrap 95% CI [−1.1,+9.3],exact McNemar p=…;方向为正但证据不确定"。区间跨 0 ≠ 完全无效;点估计为正 ≠ 显著。

## 2.6 数据增广

当前冻结身份:凡未预注册的(在线裁剪/翻转/颜色/自动改写)都不加。下一身份语义安全表:轻微亮度对比度 gamma/JPEG/噪声通常可用(颜色为标签时禁);轻微模糊可用但须验证小零件可见;水平翻转仅在无左右/列号语义时(否则同步重映射标签);垂直翻转、90° 旋转对倒放/倾倒/行列任务通常无效会改标签;随机裁剪对计数/最多区域/格位定位危险;CutMix/MixUp 不建议;simulator rerender 可以但必须继承同一 source lineage。"同图不同问法"是一条训练行,第三种改写(人工/LLM/在线)都突破每源 2 行上限;两种问法必须绑定同一划分。

# 问题 3|固定机位近重复检测

## 3.1 对当前修复的结论

保留正确的两点:仪器失效 fail-fast 不静默丢路;内部近重分量绑定同一划分而非全删。三个盲区:

1. **16/256 不是 4/64 的合理同比例扩展**:理想独立均衡 bit 模型下,64-bit 阈 4 ≈ 均值下 7σ,256-bit 阈 16 ≈ 均值下 14σ(尾概率 3.7e-14 vs 9.3e-53)。真实 pHash bit 强相关不能直接当 FPR,但足以证明"同比例不保持统计工作点";阈值只能由场景上标定的正负样本确定。且 16×16 仍是全局低频 DCT,共享背景占大部分像素时可能只是更精细地编码背景。
2. **有效性门只防过度连边,不防完全漏检**(无召回率验证)。
3. **10% 边密度门对传递闭包太晚**:550 图 150,975 对,10%≈15,098 边、平均度 54.9;随机图直觉上平均度 1 的密度仅 0.182%,近全连通量级 ≈1.15%。连"正常"的 CLIP 路(827 边、密度 0.548%、平均度 3.01)有少数跨簇桥边也可能成大分量。下一身份有效性门至少加:标定正样本召回率、task-hard negative FPR、最大连通分量占比、component size 中位/P95/最大、degree P95/最大、与保留族群相连桥边数、阈值附近人工抽查。现有三判据只能叫退化警报。

## 3.4 第一仪器应是仿真场景元数据(最大优势:场景自生成)

canonical scene signature:camera id/pose、generator version、source episode id、seed、每实例 asset/mesh id、类别与 instance id、物体世界 pose、所属格位、任务状态(upright/upside-down/tilted)、光照材质随机化 lineage。按 task-relevant 容差匹配(物体清单相同+Hungarian 对齐+关键物体位姿差低于预注册阈值,或同 rerender lineage)。

**仪器层级**:①硬证据(精确 hash、同 lineage、canonical signature、同实例近似 pose)→ 可进 union-find 传递闭包;②前景感知图像比较(instance segmentation/depth/空背景渲染;两图前景 mask 并集膨胀 3–5 px,同一全局画布坐标比较 masked RGB+depth+mask IoU;**不要**各自裁到自身 bbox——位置正是任务语义);③学习型候选检索(SSCD 拷贝检测;masked SSIM 严格像素验证;LPIPS 对齐局部感知差;DreamSim 前景/布局/语义召回;CLIP 只适合语义相似不适合近重事实判定),各自单独定标不共用阈值。

## 3.5 阈值标定

独立 calibration pair set(不触保留族群)。正样本=同场景 JPEG/resize/小幅光照/渲染噪声/轻微颜色/再编码。**task-hard negatives(绝不能合并)**=共享背景与物体种类但:零件移到相邻格、正常变倒放、倾角跨标签边界、数量±1、"最多区域"变化、两格互换。普通负样本=不同清单/明显不同布局。工作点:正样本召回 98–99% 优先,task-hard FPR 达标,报告 CI 与阈值邻域人工样本。注意:150,975 对下 FPR 1e-4 仍期望 ~15 条假边,一条成桥即污染大分量,小样本标定证明不了桥边风险——但 550 图可全对算分+人工复核全部最终候选边(至少阈值附近与每条跨大簇桥边),保存 pair montage 与判定理由。

## 3.6 "并集+传递闭包"如何改

**候选生成取并集,最终成边必须经过验证**:任一路命中→candidate queue→canonical metadata/前景 verifier/人工审查确认→只有确认后的硬边进最终图→硬边才做传递闭包。相似度阈值边不具传递性(A~B、B~C 不代表 A~C)。必须全自动聚软边时用 complete linkage/每成员匹配 cluster anchor/限制簇内最大直径,而非无条件连通分量。

**对已冻结的本轮 v2 方案:原样执行**——256-bit pHash 触发有效性门就停,不临时去路、不改 12/20 等其他阈值,报告"新仪器仍未通过预注册有效性门"(正确的阴性仪器结果)。以上新方案进下一身份。

# 问题 4|把阴性结果讲成加分项

## 4.1 首先避免的逻辑错误

不要说"经典规划成功率低,因此加入大模型指挥体"(评委会问:95 mm 的 TCP 偏差为什么靠大模型解决?)。正确表达:**大模型解决开放语言理解、场景语义和多步任务分解;严格评测暴露的 95 mm 偏差说明低层执行必须模块化、可替换并接受独立验证。**

PPT 金句:**严格协议没有把失败变成成功;它把系统瓶颈定位到了一个可替换、可验证的执行几何层。** 边界补句:**当前实现未获得"成功率≥75%"的证据,不等于任务永远不可行,也不等于高层分层架构失效。**

## 4.2 叙事顺序(7 页)

1. **一句话系统定位**:"让大模型负责理解,让可验证执行层负责动手";五模块图(图像+指令→27B 指挥体→JSON 技能契约→经典规划执行层→Isaac 机械臂)+两条恢复箭头(执行层内部/升级指挥体)。第一页不放失败数据、不先讲审计。
2. **为什么不能直接端到端**:"语言决策开放、机械执行强约束,混成黑箱则失败原因无法验证也无法恢复";大脑/小脑分工表。
3. **JSON 契约**:重点是"自然语言必须先编译成带前置条件、参数范围和成功后置条件的技能调用";示例 JSON(place part_07 → row2/col3,approach top,keep_upright,success=inside_slot+stable);强调执行层可拒绝(越界/不存在/IK 不可达/前置不满足/后置失败)。
4. **两级恢复**:"小误差由技能层闭环修复,任务语义失配才升级大模型";四例(候选 IK 失败换二候选/接近误差大重对齐/碰到其他格位重读场景重分解/任务不可达拒绝或请求人工)。
5. **严格证据链**:预注册、冻结 seed、失败计分母、不许中途调门、来源分量绑定、fail-closed 数据门、工件 hash 版本身份;"不仅记录成功了什么,还能证明成功来自哪个版本哪组冻结条件哪条执行链"。
6. **阴性结果页**(标题"冻结评测定位到执行几何瓶颈",不叫"实验失败"):三 KPI 卡(x/12、最佳接触误差 95.3 mm、门限 20 mm)+阶段漏斗标失败位置+三栏(结论:执行层 v0 未提供达标证据,异常集中在末端几何与 pre-grasp/接触阶段|不能推出:任务不可行/大模型掩盖几何错误/放宽门限回填|下一版:TCP-frame oracle→变换链修复→短程闭环接近→几何推导容差→独立重新预注册)。
7. **演示与路线图**:功能演示(illustrative)与冻结评测(confirmatory)醒目分开;新支路修好 happy path 可展示但标"vNext 工程演示,不回填 v0 冻结评测"。
