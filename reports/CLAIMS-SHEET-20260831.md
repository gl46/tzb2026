## 0e. 证据类型 → 允许推导表(第七轮审查建议,防元层错误)

**存在理由**:今晚第 4、19、21、22 条错误共同点是——**原始证据没错,错的是我们赋予它的谓词、类型、组件归属或证明范围**。哈希与 schema 挡不住这一类。本表把"某类证据只能推出什么"写死。

| 证据类型 | **只能**推出 | **不能**推出 |
|---|---|---|
| 当前文件 SHA 匹配 | 当前字节等于给定摘要 | 自冻结以来从未修改 |
| Pydantic runtime reject | **类型化契约层**拒绝 | 语义验证器拒绝 |
| test dispatcher 未调用 | 测试调用点未到达 | 机械臂保持静止 |
| 调用了生产 gate 函数 | 该函数被执行 | 末端 dispatcher 被调用 |
| family-conditioned 分数 | **已知 family 条件下**的合同生成结果 | 自主路由能力 |
| post-hoc family breakdown | 描述性逐族结果 | 预注册主要终点 |
| adapter paired delta = 0 | **当前配置**无增量收益 | 微调普遍无用 |
| synthetic/free-contact harness | 该 harness 内的行为 | 真实接触或物理执行 |

**每条对外 claim 至少携带**:`subject` / `component` / `phase` / `evidence_type` / `supported_predicate` / `unsupported_predicates`。

**可机器化的 lint(三条即可覆盖今晚多数元层错误)**
```
evidence_type = PYDANTIC_RUNTIME_REJECT  且 claim 中出现 "语义验证器/semantic validator" → FAIL
evidence_type = CURRENT_BYTES_SHA        且 claim 中出现 "自冻结以来未改/unchanged"      → FAIL
evidence_type = TEST_DISPATCHER_NO_CALL  且 claim 中出现 "机械臂/robot/物理动作"          → FAIL
```

**不可机器化的部分,只能靠人**:"这个方法论是否严谨""这个结果是否足以叫能力"含开放语义判断。剩余防线四条:
1. 独立 reviewer **直接读原工件**,不读协调者摘要;
2. reviewer 须写出"这份证据最强能证明什么"与"最容易被误写成什么";
3. 对方法论性质主张强制反事实提问:**在什么替代世界里,同样的工件仍会出现,但我要声称的结论其实不成立?**
4. 权威清单**单向生成** deck 与视频,不允许各文件手工复制(当前尚未实现,列 vNext)。
